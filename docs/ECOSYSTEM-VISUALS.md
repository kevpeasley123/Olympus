# Ecosystem visual reference pass

The initial interpretation emphasized textured planetary bodies, but operator review corrected that: the approved concept requires dark volumetric orbs, directional light/shadow, atmospheric rims, a strong gold Olympus centerpiece, and layered stars/constellations. A functional layout with gradient discs did not meet that standard.

The revised scene uses `src/assets/ecosystem-planet-gold.png`, generated with the built-in image generator, composited with hue treatments for project bodies. SVG supplies decorative stars, constellation chains and, until the cleanup below, orbital traces. Decorative connections mean connection to the Olympus hub, not project dependencies. Labels remain separate and stable. Planet area is a bounded display of recorded vault task counts; unknown stays explicitly unmeasured. These are shared terrain textures with different colors, not unique simulated planets or a physical orbital simulation.

## Asset prompt
Game UI asset: a single detailed luminous golden planet isolated on transparent background. Rocky ochre terrain, swirling pale gold clouds, fine craters and subtle fissures. Directional sunlight from upper left, pale atmospheric rim, deep lower-right shadow. Entire sphere visible, centered, no stars, text, symbols, rings or backdrop. Premium Olympus central celestial body and recolorable UI asset; detailed surface remains legible at 180px.

## Review target
Compare native ecosystem captures directly with the approved render, separately checking surface detail, atmospheric depth, star/constellation layering, central-body hierarchy, label legibility and clipping. Browser geometry tests are necessary but do not establish artistic fidelity. Native captures were inspected with eight real projects; current zero task counts correctly produce equal project-body sizes.

## Orb correction after operator review
The literal rocky-planet treatment was rejected. The current scene uses layered volumetric shading with a faint blurred cloud contribution, dark hemispheres, colored atmospheric rims and distinct colors for up to eight visible projects. The surface asset is now subordinate rather than the visual subject. Connection endpoints anchor to the sphere center, independently of label height. Clean cubic paths carry staggered animated light; this is a decorative information-link metaphor, not live network telemetry. Hidden-document pause and reduced motion apply; the manual pause control of this pass was removed in the cleanup below. Two successive native captures were inspected against the reference; the second softened specular highlights and removed the glass-like interior arc. `scripts/test-ecosystem-connections.mjs` measures all eight endpoints and verifies light movement, the absence of a pause control, and reduced motion.

## Composition correction
The operator rejected the preceding captures: functional connection tests did not establish reference fidelity. This pass replaces the equal radial layout with asymmetric, count-aware positions, places labels beside the orbs on wide panels, shortens the native eight-project scene from 668px to approximately 464px overall, and masks the environment away from the central space. ## Celestial light and semantic identities
Operator requested returning to the reference's open sky, luminous warm Omega/text, colored rims and meaningful project symbols. Added generated ecosystem-night-sky.png (built-in image generation; midnight navy stars with mountains limited to lower and outer edges, no baked UI/orbs/text). It replaces the global backdrop only while Project Ecosystem is mounted; Cards and other modes retain their existing environment. Stars and constellation beacons use pixel dimensions to avoid stretching at wide aspect ratios.

Names now select deliberate subject identities consistently across cards and orbs: Pokédex/Pokémon uses a custom Poké Ball; Olympus a mountain; learning a graduation cap; scaffolding blocks; Obsidian a network; health a heartbeat; fruit an apple; agent development a robot. Additional explicit research/studio/website/automation mappings use matching icons. Unknown names use a neutral folder; colors do not depend on sort order or opaque ID hashes. This is presentation mapping, not a claim of backend activity.

Reviewed two native passes: corrected stretched stars, restrained the upper surface brightness and protected label readability. Build, focused identity/portfolio/connection checks and final browser visual regression are tracked separately from native screenshot inspection.
