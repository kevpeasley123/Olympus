# Automatic understanding: operator correction to the implementation direction

Date: November 2, 2026, America/Phoenix.
Authority: Kevin's direct correction after reviewing the email learning milestone.
This supersedes the manual learning-interface direction in the earlier Gmail design
and implementation plan. It does not authorize new provider spending or credentials.

Kevin rejected requiring him to categorize conversations or maintain understanding
through correction/edit/undo/forget buttons. He wants Olympus to build understanding
of his projects, preferences and workflows through normal use, as an assistant does
through conversation. The added management workflow creates friction.

## Corrected default

- Automatically associate eligible conversation and source evidence with projects,
  ongoing matters, preferences and decisions; keep uncertain associations provisional.
- Use existing chat memory and email situation workers. Evaluate whether they process
  eligible new evidence, persist it correctly and retrieve it for useful briefings.
- Interpret natural corrections in context. Do not require forms, category selection,
  conversation filing or per-memory approval as the ordinary learning path.
- Keep provenance, conflict handling, correction history and undo/deletion safeguards
  behind the ordinary experience. Do not equate safeguards with a user task list.
- Ask only when unresolved ambiguity matters to a consequential outcome. Existing
  temporary-chat, source-access, action-approval and spending boundaries remain.
- Deliver useful briefs without requiring any attention-management clicks first.

## Immediate correction

Remove the newly added Correct suggestion button, correction editor and What Olympus
learned panel. Preserve source review and existing optional attention actions with
revision/account/source safeguards. Preserve existing data and recoverable Git history;
no destructive schema change. This interface correction does not make automatic
understanding operational by itself.

## Next implementation sequence

1. Audit the existing automatic chat-memory and email-analysis paths together:
   eligibility, quiet-chat watermarks, source revisions, retries, provider gating,
   persistence and recall. Distinguish blocked/unprocessed from understood/current.
2. Build offline end-to-end scenarios using synthetic conversations, changed project
   facts and email evidence. Ordinary conversation must yield useful recalled context
   and a changed brief without category labels or management actions.
3. Qualify the shared analyzer contract and repair the actual blocked path. Keep live
   generation gated until separately authorized; no paid fallback or credential change.
4. Connect ordinary conversational corrections to bounded, source-linked updates;
   explicit statements outrank inference, uncertainty remains visible when relevant,
   and temporary chats neither contribute nor consume learned memory.
5. Validate representative real briefs and native Gmail recovery when authorized.
   Optional tray persistence follows usefulness and reliability, not more controls.

Success: Kevin can talk and work normally; Olympus learns the relevant context and
produces better briefs without requiring him to organize its understanding.
