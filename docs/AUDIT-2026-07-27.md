separates confirmed facts from product interpretation so later agents can audit
the audit rather than inherit it as doctrine.

## Material findings

### Product direction had drifted

The inherited handoff declared:

- Project = execute, Command = think, Research = know;
- Pantheon should shape the assistant as a curriculum;
- Command should be one oversized sentence readable across the room;
- a scrolling Command surface was explicitly forbidden.

The operator rejected or materially revised each of those claims. They were
design history presented as current doctrine, which made them more dangerous
than ordinary stale documentation.

### The opening experience did not match the vision

Command selected one active project's `next_step`, enlarged it, and reduced all
other active projects to a count. It could not provide:

- several meaningful session paths;
- a current project vision;
- plain-language accomplishments;
- a distinction between commitments, recommendations, and warnings;
- a direct handoff into the selected project.

### Project memory lacked a living vision

Project notes had status, promotion date, and next step but no reviewable vision
or vision-review date. The assistant could therefore see tasks and decisions
without a compact statement of current purpose, while old prose could be
mistaken for permanent direction.

### The vault's operational memory was stale

- Project Olympus still named an April implementation step.
- The global task list contained starter-vault tasks that were already obsolete.
- The decision log stopped on April 26.
- Olympus Home embedded the April 25 brief.
- the User Profile remained marked `assumed` and allowed five active projects;
- Dashboard Information Architecture still made Projects the opening surface;
- Pantheon notes described the library as a substrate the assistant should
  absorb.

Generated views were structurally valid but reflected their older schema and
generation date.

### Delegation did not yet have a safe contract

Olympus had launch helpers for a small fixed tool allowlist but no coding-agent
run model, isolation contract, checkpoint policy, progress events, cancellation,
or recovery semantics. Adding a general shell command would have violated the
existing safety shape.

### “Since the last session” was undefined

Git exposes latest and last-24-hour activity, but Olympus did not persist a
reliable session boundary. Any claim about work “since your last session” would
therefore be an inference rather than a proven fact.

### Browser preview mixed sample data with live-looking language

The browser runtime necessarily uses example project data, but Command did not
label it. The write-confirmation component also attempted to subscribe to a
Tauri-only event transport and logged preview-only errors.

## Changes made on the isolated branches

- Initially rebuilt Command as a grounded multi-project session briefing. This
  placement was later rejected because it displaced Command's ambient
  instrument; the same briefing now lives in Project mode.
- Added living `vision` and `vision_reviewed` project-note fields through Rust,
  TypeScript, assistant context, and the UI.
- Kept operator commitments, Olympus recommendations, and attention items
  visibly separate.
- Added project-path filtering within Project mode and fixed task attribution
  when a project filter is active.
- Updated assistant policy to challenge weak reasoning, treat decisions as
  evidence, and pause before a conflicting better direction.
- Added one canonical Olympus manual plus thin Claude, Codex, and vault adapters.
- Defined the first safe coding-agent delegation contract without choosing an
  unverified launcher.
- Curated the vault's project memory, profile, charter, decision log, current
  brief, action policy, information architecture, and Pantheon model.
- Labelled browser preview data and removed the preview-only event error.
